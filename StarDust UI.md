# StarDust UI

Daily-dev shell at `http://127.0.0.1:6006` (`cargo run -p fs-viz`). The cosmos is the **host file tree** (this StarDust repo by default). Dumpable IR is the source of truth for Inspect; `.sd` is a copy. This file is the UI contract. It is not a language wave.

## Shell

- **Top:** Edit / View (one **2D/3D** toggle; New split; Refresh; Tile/Cascade; sort; Galaxy) / Tools (`cargo test`; **Open in Cursor**; **Refresh web**; **Keyboard shortcuts**; **Rebuild StarDust UI** — hover for **Rebuild with Python** / **LLVM** / **Haskell** / **Lean**; click the parent for an empty rebuild) | centered 18×18 luna + **StarDust** wordmark (12px chrome type, `line-height: 1`, nudged 3px down so the cap height sits with the moon; click toggles StarDust UI ↔ Windows UI; native Win32 caption unchanged) | Search (file/dir names; fixed 220px right slot, does not cover the wordmark).
- **Body:** cosmos view(s) + floating file windows | collapsible Agent (right). Collapse/open use the same 14px chevron (header points right; collapsed edge tab points left — not the word Agent).
- **Per cosmos view:** minimize (–), close (×) next to it, **star pin** (☆ / ★ toggle; no duplicates), new split (14px two-pane SVG).
- **Bottom pin area:** permanent pins + **minimized** items only (not already-visible windows). Same path + kind collapse to **one chip** (first-seen order). Label is the title, plus ` (n)` when **n** minimized copies in that group is > 1 (`Name`, never `Name (1)`). ★ if the group has a permanent pin, else ☆. Click restores the latest minimized copy (count drops); with no temps, click opens the permanent. Ctrl+click unpins the permanent and leaves minimized copies. Drag chips to change group order; that order persists.

Look: living two-layer sky (shell ambient field plus per-pane far dust that tracks that pane’s camera). Directories are soft Hubble-like nebulae or faint spirals; files are photographic cores with diffraction spikes and bloom (not graphic icons). Object glow is a bit brighter than the first Hubble pass; the void stays dark (not milky). Chrome is recessed spacecraft wells. Type is Bahnschrift / Segoe UI Variable, 12px chrome and ~9–11px star labels. Hubble-style `cosmos (1)–(5).png` stills in the repo root are look-dev only and are not loaded as UI backgrounds.

## Cosmos

Each view shows **direct children** of one directory as stars. `target/` at the StarDust root is one star; entering it still shows only that folder’s direct children. The **Desktop** view is an Explorer-like merge of the user Desktop known folder and Public/Common Desktop (see below).

- Directories pick one of ten looks from a stable name hash: emission nebula, reflection nebula, planetary nebula, supernova remnant, spiral, barred spiral, elliptical, irregular, globular cluster, edge-on disk. Files pick a spectral color (O/B/A/F/G/K/M/Wolf–Rayet) and a morphology (4-spike, 6-spike, halo, binary, Airy rings). Size still scales with zoom. Hover and select brighten the core and widen the bloom — there is no stroked ring.
- Background: a shell-wide **baked** deep field (nebulae, faint galaxies, spiked stars) with two slow parallax layers and a live twinkle overlay. Each cosmos pane also has far dust and faint nebula patches, seeded from the current folder, drawn as a **screen-space wrap** of that field so pan/orbit still parallax but **zoom-out never shows a decoration rectangle vs black void** (the tile covers the pane at every 2D scale, including CNS 36 / folder 6, and 3D orbit zoom-out). File/directory stars stay in world space. Far decorations stay **smaller** than file and directory glyphs. Pane fill stays mostly transparent so the shell sky shows through.
- Twinkle: files and dust pulse opacity and spike/halo size on staggered phases (~0.6–1.4s for files; slower and weaker for dust). Directories breathe (slow core pulse) and do not sparkle like files.
- Names are visible (stronger when zoomed in). Hover highlights. **Hold Ctrl** to emphasize nearby names (Ctrl is also the navigate modifier for click and scroll).
- Breadcrumb of the current path on the view: click an ancestor to scene-swap there (overflow menu if the path is long). Crumbs are the only visible address (no second full-path chip). Ctrl+L types a path (including drive roots); Enter goes there.
- Galaxy/force layout runs **once** per directory then freezes. Drag a star to move **only that star** (other selected stars stay put). In 3D, drag follows the cursor including height; Shift+drag moves height only. Positions persist per directory **and** separately for 2D vs 3D. Sort (Name / Type / Size) is a temporary row-major grid centered in each view; **Galaxy** restores the last galaxy/manual positions. Right-click **Image** submenu (click or hover; stays open to pick): **Set image…** (PNG/JPEG, WebView2 file dialog), **Reset image**, and for folders the built-in looks — looks persist under `--desktop`.
- New file/folder stars appear near the cursor (or view center). Existing stars stay put.

Process start root is this StarDust repo. Each split’s root is crumbs, the path field, or search. **StarDust UI** mode uses the real Desktop known-folder as the session root (including OneDrive Desktop when that is the Desktop).

## Windows Explorer / Desktop

StarDust can own **filesystem folder windows** and the **Desktop icon surface**. Taskbar, Start, Alt+Tab, UAC, Settings, and Open/Save dialogs stay Windows. This is not a Winlogon shell and not a kiosk.

- **StarDust UI / Windows UI** (click the centered luna + **StarDust** wordmark — `title` / `aria-label` is the other mode — plus the `stardust-guard` tray): StarDust UI hides Explorer desktop icons and, when `stardust-open.exe` sits next to `fs-viz.exe`, writes **HKCU** Directory/Drive `open` verbs to that trampoline (backup first). Windows UI restores that backup and shows Explorer folders/icons again. The brand click uses the same `setUiMode` path — Explorer restored, cosmos kept (`float_stardust_window`). The brand title/aria-label flips immediately, toasts **Switching…**, then success or fail (12s client timeout rather than an infinite wait). Re-entry while a switch is in flight is ignored. Switching to StarDust UI does not replace a focused **Inspect in StarDust** pane with Desktop. Tray / **Ctrl+Shift+F12** stay the emergency failsafe. No extra keyboard chord for UI mode. Mode is `%APPDATA%/StarDust/ui-mode.json` (not the registry for the in-app toggle itself).
- **Open in Explorer** uses the `explore` verb so it does not recurse through the trampoline. Recycle Bin *view*, Control Panel, and other virtual folders stay Explorer. `.lnk` shortcuts open via the OS (same as Explorer).
- **Failsafe:** `Ctrl+Shift+F12` (guard process) restores Windows UI immediately. Guard also failovers if HTTP `GET /api/healthz`, the host heartbeat, UI pulse, HKCU verbs, or desktop-icon hide-state go red (one host restart on yellow, then stay on Windows until you pick StarDust UI again). After a yellow `http-down` restart, failover only if HTTP is still down (not pulse/heartbeat yellow). That restart relaunches `--desktop` and waits boot grace (60s). Rebuild hold lasts until `rebuild_hold_until` (HTTP up does not end it). A `lastFailover` of `after-restart:http-down` from a 3s/`--headless` probe was a false alarm — **Tools → Rebuild StarDust UI** (`--desktop --replace`) re-arms; do not write AppData by hand. `stardust-guard` may stay running in Windows UI (health + hotkey); it must not refresh Explorer (`SHChangeNotify` / desktop `ShowWindow`) when Windows UI is already restored.
- **Native window:** `fs-viz --open PATH` and `fs-viz --desktop` host the UI in **WebView2** (not Edge `--app=`). While StarDust UI mode is on, `--open` still loads `?desktop=1` (work-area cover), not a captioned `?open=` window; `--desktop` always uses that cover URL. Browser accelerators stay off so in-app keys/menus run. Profile: `%APPDATA%/StarDust/webview-profile`. Taskbar/PE icon is derived white `stardust.ico`; Windows UI caption uses black `stardust-caption.ico` (`WM_SETICON` `ICON_SMALL`). Source art `luna-silhouette.png` stays black; tab favicon `luna-icon.png`. Regen: `python crates/fs-viz/assets/gen_stardust_ico.py`. Rebuild `fs-viz` to pick up the PE / caption icon (Refresh web is not enough). Default `cargo run -p fs-viz` is HTTP-only. `cargo build -p fs-viz` also lands `stardust-open.exe`, `stardust-guard.exe`, and `stardust-view.exe`.
- Desktop: StarDust is a **borderless work-area window** (no OS title bar, no inner cosmos glow) covering the wallpaper. The host window is `StarDustHost` (WebView2 child), not a clipped Edge caption. Translate prompts are suppressed (WebView2 flags + profile prefs + `translate="no"`). Win11 Spotlight paints above WorkerW children, so we do not embed into WorkerW. Switching to Windows UI restores Explorer’s desktop view and window chrome (the floated cosmos window keeps Close). The desktop cover does not show an OS Close tooltip. Leaving to another app (Cursor, Alt+Tab) and coming back **keeps the cover** and the live cosmos — **View → Refresh is not required** (Refresh remains a full reload). Every visible `StarDustHost` is restyled as the work-area cover while StarDust UI is on (captioned hosts are not skipped as already-cover); WebView2 is shown/resized/refocused on activate, and an in-flight Inspect 字 fetch retries without re-opening the session. Sleep/lid wake (`WM_POWERBROADCAST` resume) touches the host heartbeat, starts rebuild hold, then forces that cover restyle plus WebView resume so the guard does not yellow-failover (`heartbeat-stale`) across sleep. Win+D / Show Desktop unhides, restacks, and DWM-uncloaks the work-area cover if it was hidden, cloaked, or buried under Progman/WorkerW (not only when iconic); `NonRudeHWND` is set on the host and WebView2 children, and `ITaskbarList2::MarkFullscreenWindow(FALSE)` is applied on create, cover layout, and `WM_ACTIVATE` before `DefWindowProc`, so Explorer does not treat the popup as rude fullscreen (never TRUE, never `HWND_TOPMOST`, never `SetForegroundWindow` on cosmos click). Clicks still hit StarDust. A cosmos click must not restack the cover (that looks like rude fullscreen and cloaks other windows); restack only when Progman/WorkerW is above. The armed guard uses `keep_cover_if_wrong` (not a forced `FRAMECHANGED` every tick). Do not uncloak, restyle, or yellow-`http-down` restart/failover when another user app is exclusive-fullscreen FG; failsafe hotkey / tray Windows UI / open-storm / red still may. When FG returns to StarDust / shell / taskbar, the cover may restyle a captioned host back. The existing health/meta poll updates the brand title if `uiMode` changed. While IME/RIME is composing (search keyCode 229 / `isComposing` holds until `compositionend`, a real focus move off search to a non-IME control, or a non-229 key; Weasel `focusout` with null relatedTarget does not drop the hold; then 700ms quiet after `compositionend`), search does not query and the host does not ExecuteScript, MoveFocus, resize the WebView, `resumeFromHost`, or run cover layout/`FRAMECHANGED`. `WM_WINDOWPOSCHANGING` locks cover z (`SWP_NOZORDER`) while composing/IME (opening_cursor may still yield). Activate / `WM_WINDOWPOSCHANGED` must not restore cover (or resume WebView) while composing, IME UI FG, or other-app FG (`POST /api/ime`).
- **Desktop stars:** the session Desktop known folder is listed as Explorer’s merged namespace: user Desktop plus `%PUBLIC%\Desktop` (Common Desktop). User-folder names win on collision. Public-only items keep an absolute `path` so open / `.lnk` use that file (not `userDesktop + name`). Files are not copied or symlinked onto the user Desktop. Recycle Bin, Control Panel, and other virtual folders stay Explorer.
- **Login:** while StarDust UI is on, HKCU Run `StarDustUI` starts `fs-viz --desktop` at sign-in (taskbar/Start stay Windows; this is not Winlogon `Shell`). Windows UI deletes that Run value. `StarDustGuard` stays in Run for the failsafe and, while mode is Stardust, reinstalls `StarDustUI` if it is missing (path = current `fs-viz.exe`). At sign-in the cover waits until `GET /api/healthz` on `127.0.0.1:6006` returns 200 before WebView2 Navigate (boot grace 60s, then start `--desktop` and wait again); it retries Navigate on a timer so login does not end on Edge `ERR_CONNECTION_REFUSED` / 無法連線. Dual Run (`StarDustGuard` + `StarDustUI`) reuses an existing `StarDustHost` when HTTP is up — it does not WM_CLOSE the cover. A leftover `stardust-view` (taskbar) starts `fs-viz --desktop` if HTTP is down. The guard does not `taskkill` that `--desktop` host or failover to Windows while the host is still coming up (process-local boot grace, not stale `armed_at`). If mode is already Windows, it stays Windows until you pick StarDust (no UI Run key). Tray **StarDust UI** also starts `fs-viz --desktop`.

## Gestures

| Gesture | Action |
| --- | --- |
| **Click, then hold the second click and move** | Pan the camera (2D and 3D) when the second down is **empty**. On a star, the drag moves that star instead. A released double-left-click (no move) on a star opens it. |
| **Ctrl+scroll** | Camera zoom / dolly in the current scene (does not enter or leave). Always zooms; never leaves. |
| **Scroll-in** on a **directory** star | Fly-into a directory only after accumulated scroll-in on that same star; debt `100 × (720 / max(96, short))` (smaller pane → more). Until then, zoom. First event of a gesture / first event on a new star does not enter. |
| **Scroll-out** | Leave (fly-out, then parent) only when this view already frames every star (pad max(24px, 12% of the short side); 0 stars count as framed) **or** zoom-out is maxed, **and** only after a further accumulated scroll-out whose debt is `140 × (720 / max(96, short))` (smaller split → more scroll-out). A gesture that **starts** with any star clipped (wheels within 350ms are one gesture) only zooms — it never leaves. After idle 350ms+ with the scene framed, extra notches still zoom until min zoom, then wait until that debt is met; the first framed event of a gesture never leaves. Works during an in-flight fly. |
| **Ctrl+click** a star (no drag) | Toggle that star in the selection. Does **not** enter a folder or leave to the parent. Ctrl+click empty space does not clear. |
| **Shift+click** a star | Spatial range from the selection **anchor** (last plain click) to this star. Replaces the selection. **Ctrl+Shift+click** unions the range. |
| Middle-drag | 2D: pan. 3D: orbit (turntable). |

## Keyboard

In-app chords. Cosmos/file chords do not run while typing in search, the path field, rename, or a file editor (**Ctrl+S** still saves). **Agent chords** (**Ctrl+I** toggle, **Ctrl+Shift+I** focus composer, new thread, stop, send selection), **Ctrl+F5** (Refresh web), and the overlay run from anywhere, including those fields and the composer — same idea as Cursor. Enter a folder with **double-click** or **Enter**; parent with **Alt+Up**, **Backspace**, or empty **double-click**. Not in v1: Win+E, F11, Space preview, Alt+underlined menus.

Discovery: **Tools → Keyboard shortcuts**, **Ctrl+/**, or **F1** (F1 is `preventDefault` so Edge does not open its help). **Esc** closes the overlay; backdrop click also closes it.

## Windows and pins

- **Open file** (text): floating window (drag the title to move; drag any edge or the bottom-right grip to resize; **Save** on the title bar when dirty, also Ctrl+S; min/max/close). Dock into the focused cosmos view as tabs (Save is on the tab strip); undock to float. **Tile windows** / **Cascade windows** (View menu) arrange those file windows over the cosmos — they do not retile cosmos splits. If the files were docked as tabs, Tile/Cascade undock them first. Greyed out when no file window is open. Monaco editor; dirty close = Save / Don’t save / Cancel.
- **Non-text:** OS default application; no in-app editor.
- **New split:** a 14px two-pane SVG duplicates the current folder and camera into two panes along the longer edge of the focused pane (side-by-side if wider, stacked if taller); it does not open the process default root. Menu “Open in new split” still opens the chosen directory in the new pane. Further splits divide that pane the same way. Sash still resizes. File windows float over the focused view. Driven OS windows use the focused cosmos as the peek slot (not a second Desktop pane on Refresh). Dragging the OS window off that slot undocks it.
- **Minimize (–):** hide that cosmos pane to the pin bar (**one temp pin per view**, even if that folder is already ★) and **focus the latest still-open view**. If it was the only pane, a live view at the default root takes its place (no blocking overlay). File minimize is still one temp per window. Duplicate collapsed views of the same path show as one `Name (n)` chip. Restore from the pin bar.
- **Close (×):** remove that pane (no pin). The last live pane cannot be closed (use minimize).
- **Star pin:** ☆ / ★ toggles a permanent pin for the current folder (or a star from the right-click menu). The same path is stored only once. A ★ plus collapses of that folder is still one chip (`★ Name (2)` when two are minimized). Ctrl+click a ★ on the pin bar to unpin the permanent (minimized copies stay).

## Search

Name search over the tree (the current split root is included when its name matches). When the **focused pane** is **Inspect in StarDust** (CNS/Luna abstract space), type in the **Word header find box** (placeholder `Search Word / Enc / Post / Cns`; **Ctrl+F** / **Ctrl+L** focuses it) or the top-bar Search while that pane is focused. Matches **字**, Luna **Enc** / **Post**, or **Cns** (e.g. `1-5153`); choosing a hit **flies** to the already-placed 字 (does not enter the 字 neighborhood; Enc/Post/Cns do not spawn). Search still works after a neighborhood double-click: it leaves similar-words, flies on the catalog plane, then empties the box (same as file search). File-tree search: walks **all open split roots**, the **focused folder**, and also `%USERPROFILE%\Desktop`, `%USERPROFILE%\OneDrive\Desktop`, `%PUBLIC%\Desktop` (and `HOME/Desktop` off Windows) when those folders exist. Desktop extras use their own visit budget so a large repo walk cannot starve them. The dropdown shows **Searching…** immediately, then hits as they are found (`GET /api/search?stream=1`); the footer still says **Searching more folders…** until every root finishes (or **No matches**). It is `position: fixed` under the box. Results stay open until a hit is chosen, Escape, or the query is cleared; choosing a hit empties the box and the list. Rank: path jump (existing absolute path, or a child of the current search root / focused folder, hidden folders included), then the current folder, then exact / prefix name matches, directories before files. `target/`, `node_modules`, and `AppData` / `Application Data` are not listed as hits when unmatched, but a matching name or an explicit path is a jump target; search still does not recurse into those folders, so they cannot eat the visit budget. Matching sibling names in a folder are collected before descending; matching directories are descended first so Desktop is found before a deep walk can eat the visit budget. Hover or arrow on a hit uses the click-selection look on that star in every open view that shows it, or on the deepest visible ancestor folder. Enter in the search box opens a hit; cosmos Enter is ignored while the search field is focused. IME/RIME: search does not query mid-composition (`keyCode` 229); 700ms quiet after `compositionend`. While composing, the host skips ExecuteScript / MoveFocus / bounds and does not pin cover z-order (`POST /api/ime`).

## Agent

Cursor-like chat, StarDust styling, collapsible; last open/collapsed state is remembered. Threads switch from **tabs on the Agent header** (not a left rail). **+** starts a thread. A **History** clock (top-right) opens the thread-list popover. Composer mode: **Agent** / **Plan** / **Ask** (Ask is SDK `mode: "agent"` with edit/delete/applyAgentDiff disallowed — there is no SDK `"ask"`). Model dropdown, persisted per thread. There is no Rules UI; the UI does not send a user `rules` string. Sidecar always prepends the AppData lock (`UI_HINT` / `APPDATA_LOCK`) on every send, including when rules are empty. Cursor (`.cursor/rules`) may access AppData; the StarDust in-app agent still must never move, rename, copy-away, relocate, or amend Windows AppData (Roaming, Local, or LocalLow), including `%APPDATA%\StarDust`, and must not Write, Shell, copy, or delete under those trees — that lock is sidecar-only. There is no assistant-name bar on the header — the **tab is the chat title**. Built-in Cursor tools (shell, read, grep, …) stay enabled (`customTools` is additive; do not pass `tools: []`). Overlay cwd is still the temp `stardust-ws-*` junction folder, not the Desktop.

- Double-click / **F2** a thread **tab** (or a row in History) to rename that chat. Tab and list titles use a text cursor and a rename tooltip. Thread titles are PATCHed to the sidecar when it is up. A new chat stays **New thread** until the first reply finishes; then the sidecar names it (2–6 words for the user’s goal, not a slice of the prompt or an `@` filename). Tab **×** (**Close chat**) closes the tab only: the thread stays in History (`open: false` in `agent-history.json`; sidecar id is kept so resume still works). History **×** (**Delete chat**) posts `/api/agent/stop-all` then permanently removes the chat from tabs and History (saved immediately; sidecar DELETE when it is not local). Click a History row to reopen it as a tab. Closing an empty untitled **New thread** (no user/assistant text) drops it entirely so it does not leave a History ghost.
- Chat history lives in `agent-history.json` (header tabs and the History popover). Closed chats stay in History until deleted. The sidecar’s in-memory thread list is **not** imported on boot. After reload, saved messages are restored into the panel and the next send continues that thread (sidecar/SDK resume when possible; otherwise a new sidecar thread with the saved conversation prepended). Empty **New thread** tabs with no messages are dropped on load.
- Double-click a user message to edit it (assistant rows are not editable). Enter commits, Esc cancels, Shift+Enter inserts a newline. Clicking anywhere else (including empty chat, composer, tabs, or another Agent button) or a mode/model change cancels the edit without committing. If later turns exist, confirm **Discard later messages**. That truncates the thread after the edited prompt, disposes the sidecar agent, and sends the new text as a fresh run. The last user message with no later turns still recreates the sidecar agent (no confirm).
- Local TypeScript sidecar (`@cursor/sdk`). `CURSOR_API_KEY` from the environment or a gitignored local env file. Missing key: clear error, no crash. Replies stream into the panel; the workspace folder is reused until split roots change.
- Workspace is a **temporary folder** of junctions/links to every open split root, with paths mapped back in the UI when possible.
- **Send to Agent** is Cursor `@` attach of the **selected** star(s) (marquee or Shift range, not only the one under the cursor) on the **current** thread: right-click menu or **Edit → Send to Agent**. The agent panel opens with those paths as chips. On Send, every visible `@` chip is included with the prompt (file content is inlined when it is text and not huge; chips-only with an empty composer is a valid send). The send does **not** include a text snapshot of the cosmos; the agent must call tools to see the UI. While a run is in flight, the transcript shows **action** rows (Thinking…, then tool names) in the same bubble style in **stream/time order**, not parked above the reply; replies still stream. **Stop** and History **×** (**Delete chat**) post `/api/agent/stop-all` so no thread keeps driving OS windows.
- **UI tools** (Cursor SDK custom tools, focused pane only): **look-at-view** (JPEG of the focused cosmos/folder canvas — not menus or the Agent panel), **navigate** (folder path or This PC), **open** (star names/paths), **select** (star names), **pin** (star names/paths), **copy** (duplicate on real host paths; optional dest directory, omit dest to duplicate beside the source; Explorer names `Name - Copy.ext` / `Name - Copy (n).ext`; never the temp `stardust-ws-*` overlay), **search** (same ranking as the search bar), **jump** (folder in-place; file → parent + select; does not open a Windows viewer), **write-out** (generated payloads to `%USERPROFILE%\.stardust-out`; `POST /api/agent-out/write`). Temp screenshots under `.stardust-out\cap-screen` and Desktop `cap-screen*` / `wa-view*` are swept at run end (`POST /api/agent-out/sweep`). The sidecar HTTP-calls the host; the page polls a short inbox and executes via `window.SD`. The agent cwd is a temp junction overlay of split roots, not the Desktop — “Copy this file” must use **copy**, not SDK Write.

## Persistence

User config files (not in the git repo): `ui-layout.json` (pins, splits, open files, agent open/width/model, star positions/images), `agent-history.json` (assistant name, current thread, threads with messages / model / agentMode / open), and `ui-mode.json` (StarDust vs Windows UI). History is a sibling of layout under `%APPDATA%/StarDust/` (or the same config dir off Windows). Transcripts are **not** stored in `ui-layout.json`. `--desktop` / `--open` do not replace views/split/pins in `ui-layout.json`; they still merge `starPos` / `starLooks`. A failed boot `GET /api/layout` must not disable later `PUT`s; hide/`pagehide`/`beforeunload` flush layout (`keepalive` PUT so `--desktop --replace` still remembers views). Restored `path` wins over Desktop `sessionRoot`. Do not auto-split a second Desktop on Refresh. `agent-history.json` still loads and saves. Default root on a new process is this StarDust repo until a pane’s path changes, unless **StarDust UI** is on (then Desktop).

Live **watch** updates stars when the folder changes.

## Mutate and drag-and-drop

Rename, Delete (Recycle Bin), New, Copy, Cut, Paste change the real disk. Paste and New place stars near the cursor. Drag from OS Explorer into a view copies (Ctrl) or moves (Shift) when the host allows. Drag a cosmos star (or the whole selection if that star is selected) onto a **folder star** or onto **empty space in another pane** moves those files. Same-pane empty still only nudges layout. While dragging, the star image follows the pointer (including off the canvas); layout saves on pointer-up. AppData and agent temp workspaces (`stardust-ws-*`) are refused. Inspect/CNS panes do not move. No Ctrl-drag copy this round.

## Inspect and tests

- **Open** a `.sd` file: IR text in the floating editor (same as other text). That is how you read dumpable IR.
- **Inspect IR/layout:** floating pinnable window. Pretty type/field tree first; dumpable IR behind a toggle. Only `.sd` / known layouts; other files: disabled or “not a StarDust layout.”
- **Inspect in StarDust** (right-click one `.sd`): a **new cosmos split** (does not replace the folder). Close **×** / **Ctrl+W**. Only [`examples/cns_graph/world.sd`](examples/cns_graph/world.sd) is illustrated (`--features python`, `WorldLay` / `import_all` on one worker thread). Other `.sd`: menu greyed. When the host lacks python, the grey Inspect item is replaced by **Rebuild with Python to Inspect in StarDust**. Overlay **Inspect in StarDust — importing Word…** until catalog + one layout return. Default plane: all catalog words once — IDS leaves → `leaf_axis` average × 1600 + golden spiral `22√(i+1)` + jitter ±48 + 16 force iterations (coeff 0.018). Not Jaccard embedding, not a rim/origin hub. `layout_seed` is process-lifetime (leaf_axis + spiral phase only). Same path reuses session `placed` (no second import). Frustum `STAR_CAP` 700. 字 sprites stay small (folder Hubble `starR` max 34 is files). Inspect zoom 2D ~36 / 3D min ~15 (folder 6 / 60). Search flies to the already-placed 字; Enc/Post/Cns do not spawn. Double-click enters Jaccard neighborhood (cap 80). Leave neighborhood: **Escape**, **Alt+Up**, or empty-cosmos double-click (Inspect stays open). Header find: `Search Word / Enc / Post / Cns` (**Ctrl+F**). Stale session: retry `POST /api/cns/open` once. Pane is ephemeral (not a filesystem path). Host layout: **Tools → Rebuild StarDust UI**.
- **Tools → cargo test** runs `cargo test` (default features) in the cosmos root (StarDust repo / focused project) in a pinnable window. The wait line ticks elapsed seconds until cargo returns. On Windows GNU, if `CARGO_TARGET_X86_64_PC_WINDOWS_GNU_LINKER` is unset, the host picks rustc’s self-contained `x86_64-w64-mingw32-gcc.exe` from one rustup toolchain directory (no recursive `.rustup` walk). The agent may also run tests.
- **Tools → Open in Cursor** opens the Cursor GUI on this StarDust repo folder (same `workspace_root` as Rebuild). `POST /api/open-cursor` `PostMessage`s `StarDustOpenCursor` to `StarDustHost`; the view thread `ShellExecuteW`s `Cursor.exe` with `--classic --new-window "<folder>"` (flags before the folder; not `cursor.cmd`, and not `CREATE_NO_WINDOW` — that hid the window) and yields cover z-order ~4s so Cursor can come in front (never `HWND_TOPMOST`). `--classic` matches the classic editor (a tab appears only when the user clicks a file; newer Agents/Glass auto-opens edited files). `--new-window` so an already-running Cursor cannot swallow the click. Typical path `%LOCALAPPDATA%\Programs\cursor\Cursor.exe` (also `Program Files\cursor\Cursor.exe` and `Program Files (x86)\cursor\Cursor.exe`). Toast if Cursor is missing or there is no `StarDustHost`.
- **Tools → Refresh web** (Ctrl+F5) reloads the page from `crates/fs-viz/web/` on disk (layout flushed first); it does **not** run Cargo or relaunch `fs-viz.exe`. Use this after JS/CSS/HTML edits. Rebuild remains the native compile + `--desktop --replace` path.
- **Tools → Rebuild StarDust UI** is `cargo build -p fs-viz` then `--desktop --replace` (GNU linker on this host). Empty Rebuild (click the parent) keeps **this** binary’s features. Hover shows **Rebuild with Python** / **LLVM** / **Haskell** / **Lean** (and the `.sd` context-menu python rebuild) which **union** those names onto the current set. Inspect in StarDust still needs python. Helper spawns null stdin/stdout/stderr (`CREATE_NO_WINDOW`) because `--desktop` `FreeConsole` makes inherited handles invalid (os error 6); cargo then re-pipes stdout/stderr to capture the log. It must not open Explorer. Guard yellow recovery is held ~660s until `rebuild_hold_until` (HTTP up does not clear the hold). Tray **Open Desktop in Explorer** and in-app **Open in Explorer** stay. Layout/pins restore by directory path identity; rebuild flushes layout first.
